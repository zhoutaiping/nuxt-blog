# 服务端渲染与边缘计算

2026 年，服务端渲染（SSR）与边缘计算（Edge Computing）正在深度融合，为前端应用带来更快的加载速度和更好的用户体验。

## 服务端渲染（SSR）的演进

### 传统 SSR

传统 SSR 是在服务器上渲染页面，然后发送给客户端：

```javascript
// Next.js 页面级 SSR
export async function getServerSideProps() {
  const data = await fetchData()
  return { props: { data } }
}
```

### 增量静态再生成（ISR）

ISR 允许在构建后更新静态页面：

```javascript
// Next.js ISR
export async function getStaticProps() {
  const data = await fetchData()
  
  return {
    props: { data },
    revalidate: 60 // 每 60 秒重新验证一次
  }
}
```

### 流式 SSR

流式 SSR 允许逐步发送 HTML，提升首屏加载速度：

```jsx
// React 18 流式 SSR
import { renderToPipeableStream } from 'react-dom/server'

const { pipe } = renderToPipeableStream(<App />, {
  bootstrapScripts: ['/main.js'],
  onShellReady() {
    res.statusCode = 200
    pipe(res)
  }
})
```

## 边缘计算（Edge Computing）

边缘计算将计算从中心服务器移近到用户：

### Edge Functions

Edge Functions 是在边缘节点上运行的无服务器函数：

```javascript
// Next.js Edge Function
export const config = {
  runtime: 'edge'
}

export default function handler(req) {
  const geo = req.geo
  const country = geo.country || 'US'
  
  return new Response(`Hello from ${country}!`)
}
```

### 边缘渲染（Edge SSR）

边缘渲染将 SSR 放到边缘节点执行：

- 更低的延迟
- 更少的服务器负载
- 更好的用户体验

## 深度融合

SSR 与边缘计算的深度融合带来了新的架构模式：

### 边缘优先架构

1. **静态资源**：CDN 边缘节点
2. **API 请求**：边缘函数处理
3. **动态渲染**：边缘节点 SSR

### 实战案例

```javascript
// Next.js 13+ 应用路由
// app/page.tsx
async function getData() {
  const res = await fetch('https://api.example.com/data', {
    next: { revalidate: 60 } // ISR
  })
  return res.json()
}

export default async function Page() {
  const data = await getData()
  
  return (
    <main>
      <h1>{data.title}</h1>
      <p>{data.description}</p>
    </main>
  )
}
```
